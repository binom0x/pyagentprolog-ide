## 1. Что это

IDE для разработки гибридных Prolog-программ на PyAgentProlog. Позволяет:

- писать и проверять Prolog-программы;
- подключать Python-действия из `my_actions.py`, лежащего рядом с `kb.pl`;
- давать действиям доступ к внешним ресурсам (LLM, БД, API) через `context`;
- включать семантическую унификацию (сравнение атомов по смыслу);
- выполнять запросы с таймаутом, стримингом, трассировкой, точками останова;
- смотреть базу знаний, индекс и диагностику.

Всё работает поверх пакета `pyagentprolog` (ядро) и `gradio` (веб-UI). IDE — отдельный пакет `pyagentprolog-ide`; ядро о ней ничего не знает.

## 4. Колонка 1 — Проект и настройки

### 4.1. Что такое «проект»

**Проект** — это папка, в которой лежат:

```
my_prolog_project\
├── kb.pl            ← программа Prolog (обязательно)
└── my_actions.py    ← Python-действия (опционально)
```

Всё, что вы делаете в IDE, привязано к одной папке проекта. При смене проекта `Agent` пересоздаётся, действия из старого `my_actions.py` не переносятся.

### 4.2. 📄 Drag-drop `.pl` (сверху)

**Что делает:** берёт файл, читает содержимое и **кладёт в редактор** (колонка 2). **Проект не меняет.**

⚠ **Важно:** Gradio при загрузке файла всегда копирует его во временную папку сервера (`/tmp/...`). Реальный путь к исходному файлу недоступен. Поэтому даже если вы перетащили `D:\Projects\X\kb.pl`, IDE **не узнает**, что проект — `D:\Projects\X`.

**Когда использовать:** быстро посмотреть чужой `.pl`, сравнить два варианта, скопировать фрагмент.

**Когда НЕ использовать:** хотите работать с проектом — см. 4.3/4.4.

### 4.3. 📂 Открыть

Открывает существующий проект.

**Если поле пути пусто** → откроется нативный диалог выбора **`.pl` файла** (файлы видны рядом с подпапками, не только папки). Выбираете `kb.pl` (или любой другой `.pl`) → загружается, `project_path` заполняется, статус показывает:
```
✓ Проект: D:\Projects\my_prolog
  kb:            kb.pl
  my_actions.py: есть
```

**Если поле пути не пусто** → диалог не открывается, работает по введённому пути:
- путь к папке → ищет `kb.pl`, иначе первый `.pl`;
- путь к файлу `.pl` → грузит именно этот файл, папка = родительская.

**Что происходит под капотом:** `set_project()` + `load_kb_from_project()` → `Agent(text, context=...)` → `_load_project_actions()` (импорт `my_actions.py`, если есть).

### 4.4. 🆕 Создать

Всегда открывает нативный диалог выбора/создания **папки**.

**Что делает:**
1. Создаёт папку (если её нет).
2. Кладёт туда `kb.pl` с шаблоном, если его нет:
   ```prolog
   % Новый проект PyAgentProlog.
   % my_actions.py рядом с kb.pl будет загружен автоматически.
   
   start :-
       write('Hello, PyAgentProlog!'), nl.
   ```
3. Устанавливает проект, грузит `kb.pl` в редактор.

**Когда использовать:** начинаете новую программу с нуля.

### 4.5. 💾 Сохранить

Сохраняет содержимое редактора в `kb.pl` **текущего проекта**.

**Логика:**
- поле `project_path` пусто → сохраняет в `ide.project_dir` (то, что было открыто/создано);
- поле заполнено и отличается от текущего → `set_project(path)` (переключает проект) → сохраняет туда;
- проекта нет вообще → `✗ Проект не выбран`.

**Важно:** `Save` **не** перезагружает `Agent` — это просто запись файла. Чтобы новый код заработал в запросах, нажмите **🔄 Перезагрузить** (колонка 2) или просто выполните запрос (изменение текста в редакторе автоматически триггерит пересоздание `Agent`).

### 4.6. 📚 Примеры

Открывает диалог выбора `.pl` в `pyagentprolog_ide/examples/`. Внутри — подпапки-проекты:

```
examples/
├── family/kb.pl
├── factorial/kb.pl
├── lists/kb.pl
├── cut_ite/kb.pl
├── breakpoints/kb.pl
└── semantic/kb.pl
```

Выбираете пример → становится текущим проектом (это **настоящий** проект, не временная копия). Можно экспериментировать, а потом `Save` — изменения сохранятся в примере. Чтобы не портить примеры, скопируйте их в свою папку и откройте копию.

### 4.7. 🔌 Контекст

Позволяет положить внешние ресурсы (LLM-клиент, БД, API-ключи) в `agent.context`. Внутри действий доступны через `context['key']`.

**Поля:**
- **Ключ** — имя, например `llm`, `db`, `api_key`.
- **Python-выражение** — код, который выполнится через `eval` в глобальном namespace, результат попадёт в `context[key]`.

**Кнопки:**
| Кнопка | Действие |
|---|---|
| ➕ | Вычислить выражение, положить в `context` |
| 🗑️ | Удалить `context[key]` |
| 🔄 Применить | Пересобрать `context` (вызвать builders) и перезагрузить `Agent` — действия увидят новое |
| 🔄 Список | Показать `[{key, type, repr}]` |

**Пример:**
```
Ключ:  llm
Выражение: __import__('langchain_openai').ChatOpenAI(model='gpt-4o-mini')
```
→ ➕ → 🔄 Применить.

**Замечание:** `eval` выполняется в том же процессе, что и IDE. Не выполняйте код из недоверенных источников. Если нужны builders (клиент, который нельзя переиспользовать между перезагрузками) — задавайте через Python-API (`ide.context.add_builder(fn)`), а не через UI.

### 4.8. 🧬 Semantic

Включает семантическую унификацию — сравнение атомов по смыслу через эмбеддинги. Полезно для нечёткого сопоставления: `city(moskva)` ↔ `city(moscow)`.

**Поля:**

| Поле | Назначение |
|---|---|
| Backend | `st` (sentence-transformers) или `ollama` |
| Model | Имя/ID модели для префикса и fallback загрузки (например, `paraphrase-multilingual-mpnet`, `e5-large`) |
| Local path | Точный путь к папке HF-модели (например, `D:\hf_embedding\paraphrase-multilingual-mpnet`) |
| Только локально | Если папки нет — ошибка, а не загрузка с HF |
| Threshold | Жёсткий порог `cos` (Layer 3) |
| Soft cos min | Нижняя граница `cos` для soft-коридора (Layer 2b) |
| Lev max | Максимальное `lev_ratio` для soft-коридора |
| Lev typo max | Верхняя граница `lev_ratio` для «опечаток» (Layer 2a) |

**Кнопки:**
| Кнопка | Действие |
|---|---|
| ✅ ON | Создать `EmbeddingUnifier` с заданными параметрами |
| ❌ OFF | Отключить (снять унификатор) |
| 🔧 Thr | Поменять только `threshold` у активного унификатора (без перезагрузки модели) |
| 🔄 | Обновить статус |

**Статус-бейдж** над полями: `🟢 ON` / `🔴 OFF` + backend + threshold + soft_cos_min.

**Логика локальной модели:**

| Local path | Только локально | Что произойдёт |
|---|---|---|
| Заполнен, папка есть | любое | Загрузка **только** из папки, без сети |
| Заполнен, папки нет | ☐ | Fallback: загрузка с HF по `Model` |
| Заполнен, папки нет | ☑ | ✗ Ошибка |
| Пуст | ☐ | Обычный режим (HF-кэш или загрузка с HF) |
| Пуст | ☑ | Ошибка (`local_files_only=True` без пути) |

**🔬 Проверка пары строк** — встроенный диагностический инструмент:
- вводите `A` = `moskva`, `B` = `moscow` → 🔬;
- получаете JSON: `cos`, `lev`, `verdict` (`exact`/`typo`/`hard`/`soft`/`NONE`), текущие параметры;
- если `verdict = NONE` — блок `hints` подскажет, какие именно слайдеры крутить.

**Типичный случай:**
```
cos = 0.62, lev = 0.5, threshold = 0.82, soft_cos_min = 0.55, lev_max = 0.35
verdict = NONE
hints = ["cos=0.620 в soft-коридоре, но lev=0.500 > lev_max=0.35 → увеличьте Lev max до 0.55"]
```
→ двигаете `Lev max` на 0.55 → ✅ ON → 🔬 → `verdict = soft`.

**Когда что:**

## 6. Колонка 3 — Запрос и отладка

### 6.1. Поле запроса

Введите запрос Prolog **с точкой в конце**:

```prolog
parent(ivan, X).
```

Без `?-` — IDE сама его не ждёт. Точка обязательна.

### 6.2. Timeout

Одно числовое поле. Значение по умолчанию — 30 секунд, допустимо 0.5–600.

**Семантика разная для разных кнопок:**

| Кнопка | Timeout = |
|---|---|
| ▶ Run | Общий wallclock на **весь** запрос |
| ⏩ First | То же |
| 📡 Stream | **Таймаут на каждое следующее решение** (per-item) |
| 🔍 Trace | Общий wallclock на сессию трассировки |

**Если поле пусто/невалидно** (`""`, `"abc"`, `0`, `-5`) → используется `30.0`. `ValueError` не будет.

**Что значит «таймаут»:** через N секунд IDE вернёт `⏱ Таймаут Ns` и **перестанет ждать**. **Запрос не убивается** — daemon-поток продолжает крутиться в фоне. Prolog без явной отмены (`CancelToken` в ядре) не поддерживает прерывание. Если выполнили бесконечный `loop :- loop.` — перезапустите IDE, чтобы освободить поток.

### 6.3. Кнопки ▶ ⏩ 📡 ⏹

Расположены **в один ряд под Timeout**, иконки-только:

| Кнопка | Действие | Что выводит |
|---|---|---|
| ▶ | Run — все решения | `Результат` (текст) + `Raw` (JSON) |
| ⏩ | First — первое решение | То же |
| 📡 | Stream — по одному через `agent.stream()` | `Stream` (накопительно) |
| ⏹ | Stop — прервать стриминг | Останавливает **обновление UI**; фоновый поток дойдёт до конца |

**Результат** — человеко-читаемый текст: `X = petr`, `── 3 решение(й) ──`.
**Raw (JSON)** — сырой ответ `Solver.find_solutions`: `{"query": ..., "solution": [...], "output": ..., "count": ...}`.

### 6.4. Stream (накопительно)

Каждое новое решение добавляется строкой JSON. Полезно для больших результатов и для наблюдения за прогрессом.

### 6.5. Трассировка и точки останова

**Поле breakpoints** — список предикатов через запятую:
```
loop, grandparent, ancestor
```

**Кнопки в один ряд под полем:**

| Кнопка | Действие |
|---|---|
| 🔍 Trace | Запустить запрос с трассировкой и точками останова |
| ⏵ Cont | Продолжить после паузы |
| ⏭ Step | Один шаг (продолжить до следующего breakpoint) |
| ⛔ Abort | Прервать трассировку |
| ↺ Reset | Сбросить счётчик срабатываний и паузу |

**Как это работает:**
1. В breakpoints пишете `loop`.
2. 🔍 Trace → начинает выполняться.
3. На первом вызове `loop` — **пауза**, статус `⏸ Пауза: loop(...) | Hit: 1`, кнопки `⏵ ⏭ ⛔` становятся активными.
4. ⏵ Cont → продолжить до следующего `loop`.
5. ⏭ Step → один шаг.
6. ⛔ Abort → прервать.

**Технически:** `BreakpointTracer` подменяет `ProofTracer.end_goal` и блокирует solver-поток на `threading.Event`. UI пробуждает через `controller.resume(action)`.

### 6.6. Дерево доказательства (HTML)

После Trace — визуальное дерево с вложенными `<ul>/<li>`:

- **Зелёный** — шаг успешен.
- **Красный** — провал.
- **Фиолетовый** — builtin (встроенный предикат).
- `⇐ rule` — какое правило применилось.
- `[X=petr]` — унификации головы.

### 6.7. Шаги (Dataframe)

Таблица из всех шагов: `id | goal | rule | ok | kind`. **Клик по строке** → в `subst` показывается `subst_before/subst_after` для этого шага.

### 6.8. subst (Dataframe)

`var | before | after`:
- если `ProofTracer` заполнил `subst_before/after` — показывает реальные до/после;
- иначе fallback на `unification` (bindings головы правила) — «after», «before» пустой.

Полные `before/after` включаются патчем в ядре (`interpreter.py`): после `trace_step = self.tracer.start_goal(...)` добавить `self.tracer.set_substitutions(frame.subst, new_subst)`.

## 8. Разработка Prolog-программ

### 8.1. Рабочий цикл

1. **Написать** правило/факт в редакторе.
2. **✓ Синтаксис** — быстрая проверка парсинга.
3. **🔄 Перезагрузить** — пересоздать `Agent` (проверить, что все правила загрузились: `✓ Загружено: N правил(о); ...`).
4. **▶ Run** с запросом.
5. Если что-то не так → **🔍 Trace** с breakpoints на подозрительных предикатах.
6. Доработать → **💾 Сохранить**.

### 8.2. Что поддерживается (кратко)

**Управление:** `,` `;` `->` `!` `\+` `repeat` `fail` `true`.

**Арифметика:** `is`, `>`, `<`, `>=`, `=<`, `=:=`, `=\=`, `+`, `-`, `*`, `/`, `mod`, `div`, `abs`, `sqrt`, `sin`, `cos`, `max`, `min`, `**` и др.

**Списки:** `member/2`, `append/3`, `length/2`, `memberchk/2`.

**Мета:** `call/1..5`, `once/1`, `ignore/1`, `forall/2`, `findall/3`, `bagof/3`, `setof/3`.

### 8.3. Частые ошибки

| Симптом | Причина | Решение |

| `✗ Ошибка ...` при 🔄 | Синтаксическая ошибка | ✓ Синтаксис покажет место |

## 9. Python-действия (`my_actions.py`)

### 9.1. Что это

`my_actions.py` — обычный Python-модуль рядом с `kb.pl`. IDE импортирует его автоматически **при загрузке/перезагрузке программы**, если файл существует. Меняется файл (по `mtime_ns` + `size`) → реимпорт при следующем 🔄.

### 9.2. Три вида декораторов

#### simple_action — функция → одно решение

```python
from prolog.actions import simple_action

@simple_action('distance', 3, output_arg=2)
def distance(x, y, context):
    tx = context.get('target_x', 10.0)
    ty = context.get('target_y', 5.0)
    return ((x - tx) ** 2 + (y - ty) ** 2) ** 0.5
```

- `name='distance'`, `arity=3`: предикат `distance/3`.
- `output_arg=2`: третий аргумент Prolog — выход (0-based: 0, 1, 2).
- В Python приходят `x, y` (входные) + `context` (не из Prolog, а `database.context`).
- Функция **возвращает** значение → унифицируется с `output_arg`.

В Prolog:
```prolog
near(X, Y) :- distance(X, Y, D), D < 3.0.
```

#### effector_action — side effect, без возврата

```python
from prolog.actions import effector_action

@effector_action('log_msg', 1)
def log_msg(msg, context):
    print(f"[LOG] {msg}")
    # можно писать в файл, вызывать API, мутировать context
```

Все аргументы — входные, должны быть конкретизированы до вызова.

```prolog
run :- log_msg('start'), do_work, log_msg('done').
```

#### generator_action — итератор → много решений

```python
from prolog.actions import generator_action

@generator_action('count_to', 2, output_arg=1)
def count_to(n, context):
    for i in range(1, n + 1):
        yield i
```

```prolog
?- count_to(3, X).
X = 1 ; X = 2 ; X = 3.
```

### 9.3. Что **не нужно** делать

❌ **Не** вызывайте `agent.register_action(...)` внутри `my_actions.py`. IDE делает это сама через `agent.register_action_module(mod)`.

❌ **Не** импортируйте `agent` из `prolog` и не создавайте `Agent()`.

❌ **Не** используйте `sys.path.insert` для подгрузки из своего проекта — IDE уже добавила папку проекта в `sys.path` (`register_project_dir`). Импортируйте соседние модули свободно:
```python
# my_actions.py
from my_helpers import compute  # лежит в той же папке проекта
```

### 9.4. Правила хорошего тона

1. **Только декораторы + функции**, без сайд-эффектов на уровне модуля.
2. **`context`** — единственный способ дотянуться до внешних ресурсов.
3. **Исключения внутри действий** ловятся в `wrapper` и превращаются в `fail`. Если хотите явную ошибку — `raise PrologError(...)`.
4. **Не блокируйте** надолго — таймаут запроса не убивает поток.

### 9.5. Про `context`

```python
@simple_action('ask_llm', 2, output_arg=1)
def ask_llm(prompt, context):
    llm = context.get('llm')
    if llm is None:
        return "(no llm configured)"
    return llm.invoke(prompt).content
```

`context` — это `dict`, заполненный через колонку 1 → 🔌 Контекст. IDE хранит `ContextRegistry.values` (статика) + `builders` (функции пересборки) и при пересоздании `Agent` вызывает `context.apply()` → прокидывает в `Agent(text, context=ctx)` → `Solver → Database → database.context`.

## 10. Трассировка и точки останова (практика)

**Сценарий:** правило `ancestor` не находит `ancestor(ivan, sergey)`.

1. **Программа:**
   ```prolog
   parent(ivan, alexey).
   parent(ivan, maria).
   parent(alexey, petr).
   parent(maria, sergey).
   ancestor(X, Y) :- parent(X, Y).
   ancestor(X, Y) :- parent(X, Z), ancestor(Z, Y).
   ```

2. **Запрос:** `ancestor(ivan, sergey).`

3. **Trace с breakpoints** `ancestor, parent`.

4. IDE показывает:
   - `⏸ Пауза: ancestor(ivan, sergey) | Hit: 1`
   - `⏵ Cont` → пауза на следующем `ancestor` → `⏵ Cont` → ...
   - В какой-то момент пауза на `parent(maria, sergey)` → видно, что правило `parent/2` совпадает.

5. После завершения — HTML-дерево: зелёный `ancestor(ivan, sergey)`, вложенные узлы. Красная ветка `parent(ivan, petr)` (fail) показывает, что ветка не сработала.

6. **Dataframe «Шаги»**: клик по строке `ancestor(ivan, sergey)` → `subst` покажет `X=ivan, Y=sergey` (или bindings головы).

7. **Если правило не сработало** — `📚 KB` → видно, что правило распарсилось иначе (например, `a ; b, c` → `a ; (b, c)` — не то, что вы ожидали).

## 13. База знаний и индекс

Раскройте **📚 База знаний** (колонка 2).

### 13.1. Правила

Список всех записей `agent.solver.database.rules`:

```json
[
  {"index": 0, "head": "parent(ivan, alexey)", "body": "", "rule": "parent(ivan, alexey)."},
  {"index": 1, "head": "grandparent(X, Z)", "body": "parent(X, Y), parent(Y, Z)", "rule": "grandparent(X, Z) :- parent(X, Y), parent(Y, Z)."}
]
```

**Что смотреть:**
- как правило **распарсилось** (скобки, приоритеты);
- порядок правил;
- факты (`body == ""`) vs правила.

### 13.2. Индекс

```json
{
  "parent/2":    {"rules": 3, "const_keys": ["ivan", "alexey"]},
  "grandparent/2": {"rules": 1, "const_keys": []}
}
```

`const_keys` — значения **первого аргумента**, для которых есть быстрые bucket'ы. Если у вас `parent(ivan, X)`, движок сначала смотрит в `const['ivan']` (2 правила), а не в `all` (3). На больших KB разница в разы.

**Что смотреть:**
- есть ли `const_keys` у «горячих» предикатов;
- если нет, но запросы с константным первым аргументом частые — стоит переписать предикат (вынести константу в первый аргумент).

## 16. Известные ограничения

### 16.1. Timeout не убивает запрос

Daemon-поток продолжает крутиться. Не запускайте `loop :- loop.` много раз. Для настоящей отмены нужен патч ядра (`CancelToken` в `interpreter._solve_iterative`).

### 16.2. Drag-drop не устанавливает проект

Gradio копирует файл во временную папку. Для работы с проектом — 📂 / 🆕.

### 16.3. `subst_before/after` пусты по умолчанию

`ProofTracer` не заполняет их без патча `interpreter.py`. Fallback — `unification` (bindings головы), этого обычно достаточно.

### 16.4. Semantic требует установки

- `st` → `pip install sentence-transformers` + скачивание/локальная модель.
- `ollama` → сервер на `http://localhost:11434`.

Без этого ✅ ON вернёт `✗` с подсказкой.

### 16.5. Изменения в `my_actions.py` требуют реимпорта

Автоматический реимпорт — только при перезагрузке `Agent` (🔄 или при изменении текста). Если поправили `my_actions.py` и хотите проверить без перезагрузки программы — 🔄 Перезагрузить (текст редактора тот же, но `Agent` пересоздаётся, `my_actions` переимпортируется).

### 16.6. `eval` в контексте

Выполняется в процессе IDE. Не используйте для недоверенных данных.

## 17. Горячие советы

1. **Всегда** держите `📚 KB` под рукой — быстрый sanity-check парсинга.
2. **Breakpoints** — лучший инструмент отладки; ставьте на 2–3 ключевых предиката.
3. **🔬 compare** — не гадайте, почему semantic не сработал: инструмент прямо пишет, какой слайдер крутить.
4. **Timeout 30s** — разумный дефолт; для интерактивных экспериментов ставьте 5–10s.
5. **Stream** — единственный способ увидеть прогресс долгого запроса; Run/First просто ждут конца.
6. **`my_actions.py`** — только декораторы и функции, никакой регистрации.
7. **`context`** — единственный канал к LLM/DB/API; не пытайтесь импортировать их внутри `my_actions.py` напрямую, если нужна перезагрузка без утечки старого клиента.
